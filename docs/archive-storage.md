# 월별 아카이브 저장과 조회

뉴스와 브리핑은 처음부터 해당 월 파일에 저장합니다. 지난달 파일은 조회 가능한 원본으로 남으며, 별도 복제본으로 옮긴 뒤 지우는 방식이 아닙니다. Git 이력이 이전 버전의 복구 지점입니다.

## 파일과 날짜 기준

```text
data/
  catalog.json          # version 2: 월 목록·건수·SHA-256·기사 날짜·수집 구간
  sources.json          # version 1: 현재 및 과거 기사에 쓰인 출처
  news/2026-10.json     # version 1, month, articles
  news/2026-11.json
  briefings/2026-10.json # version 1, month, editions
  briefings/2026-11.json
.runtime/
  archive-index-*.sqlite3 # 다시 만들 수 있는 로컬 조회 색인
  archive-transaction/   # 저장 중 변경 파일의 복구 저널; 성공하면 제거
  summary-attempts.json  # 유료 요청 대기 상태; 별도 보존 필요
  last-run.json
```

- 뉴스는 **원문 발행일을 KST로 변환한 월**, 브리핑은 **발행일의 월**입니다. 9월 30일 15:00 UTC는 10월 1일 KST이므로 10월 뉴스 파일에 들어갑니다.
- 매월 1일의 06:30 브리핑은 전월·당월 파일에서 06:00~06:00의 24시간 자료를 함께 읽습니다. 수집은 기존 6시간 간격을 유지합니다.
- 과거 달의 동일 기사 재수집·출처 추가·정정은 해당 월만 갱신합니다. 기사 ID·`/news/ID/`·북마크·`/briefings/YYYY-MM-DD/` 주소는 유지합니다.
- 숨김 요청은 과거 월도 찾아 반영하고, 해당 기사를 인용한 과거 브리핑은 기존 정책대로 내용이 제거된 비공개 기록으로 바꿉니다.
- 출처를 수집 설정에서 제거해도 과거 링크가 깨지지 않도록 출처 메타데이터를 비활성 상태로 보존합니다.
- 공개 데이터에 원문 전문이나 키를 추가하지 않습니다. 월별 JSON은 저장소의 원본이며 Pages 빌드는 여기서 HTML과 검색 색인을 생성합니다. `dist/`는 배포 산출물이며 Git에 커밋하지 않습니다.

## 검색과 페이지 이동

아카이브는 **18개**, 브리핑 히스토리는 **12개**, 통합 검색은 **18개** 단위입니다. 모든 카드를 HTML에 넣고 숨기던 방식과 더보기 누적 방식을 제거했습니다. 이전·다음과 페이지 번호를 이용합니다.

전체 뉴스의 기본 목록은 HTML에 포함된 **현재 페이지 18건을 즉시 표시**합니다. 초기 진입에서 목록을 숨기거나 검색 색인을 다시 읽지 않습니다. 일반 페이지 이동에는 `dist/archive/data/<version>/<page>.json`의 18건 이하 데이터 파일 하나만 요청하며, 최근 3페이지를 메모리에 보관합니다. 이 파일은 월별 원본에서 빌드한 정적 산출물이므로 별도 서버나 DB가 필요 없습니다. 기사·출처 데이터의 버전이 주소에 포함되어 수집 전후 페이지가 섞이지 않으며, 이전 버전 파일이 사라지면 현재 HTML을 한 번 새로 읽습니다. 계속 실패하면 재시도 안내를 표시합니다.

검색어나 필터를 사용하면 Pagefind 검색 색인을 읽습니다. 빌드 시 모든 월의 기사·브리핑을 색인에 포함하고, 브라우저는 전체 기간의 결과 ID를 찾은 뒤 **현재 페이지의 상세 데이터만** 읽습니다. 키워드 검색은 Pagefind의 단어·접두 검색을 따르며 임의의 중간 부분 문자열이나 한국어 어간 검색까지 보장하지 않습니다.

아카이브의 카테고리 탭·날짜·출처·지역·요약 여부·북마크와 카드/리스트 보기는 함께 사용할 수 있습니다. 날짜는 KST의 시작일·종료일을 모두 포함하며, 여러 출처가 병합된 기사도 어느 출처로든 찾을 수 있습니다. 검색·필터는 첫 페이지부터 다시 조회합니다. 페이지·필터는 URL에 남아 새로고침과 뒤로가기 시 복원됩니다. 북마크는 기존 브라우저 저장소를 그대로 사용합니다.

JavaScript가 없어도 `/archive/page/2/`, `/briefings/page/2/` 같은 정적 페이지로 전체 목록을 이동하고 본문을 읽을 수 있습니다. 검색·필터·북마크는 JavaScript가 필요합니다. 검색 파일을 읽지 못했을 때는 빈 결과와 구분하여 재시도 안내를 표시합니다.

## 수집 비용과 검증

수집기는 SQLite **로컬 파일**에 기사 ID·원문 URL·정규화된 제목·월과 브리핑 참조만 색인합니다. Python 표준 라이브러리를 사용하므로 추가 DB 서버나 Docker가 필요 없습니다. 색인으로 현재 수집 기간·중복 기사·정정 대상이 있는 월만 찾습니다. 처음 실행하거나 색인이 없어지면 월별 원본을 읽어 재생성합니다. GitHub Actions의 새 실행기는 원본을 다시 색인할 수 있습니다.

```bash
# 모든 월과 ID, 참조, 날짜, 파일 해시 검사: CI·이관·수동 점검용
.venv/bin/python -m collector validate
# 운영 래퍼: 검증된 로컬 색인의 해시와 달라진 월만 읽음
.venv/bin/python -m collector validate --incremental
```

증분 검증은 원본이 Git으로 관리되고 래퍼 실행 전 작업 트리가 깨끗하다는 전제를 사용합니다. 수동 데이터 편집 뒤에는 전체 검증을 실행하세요. CI와 정적 빌드도 모든 월을 검증합니다. `.runtime/archive-index-*.sqlite3`는 실행 중이 아닐 때 지워도 다시 만들어집니다. **`summary-attempts.json`은 중복 과금 방지 상태이므로 함께 지우지 마세요.**

## 이관과 복구

저장소에 포함된 기존 기사·브리핑은 이번 변경에서 이관했습니다. 운영 체크아웃이 깨끗하면 main을 받는 것으로 새 구조를 사용합니다. 별도 보관한 구형 `news.json`/`briefings.json`을 이관할 경우:

```bash
.venv/bin/python -m collector migrate --data-dir /path/to/data --runtime-dir /path/to/runtime
.venv/bin/python -m collector validate --data-dir /path/to/data --runtime-dir /path/to/runtime
```

명시적 이관은 원본을 검증한 뒤 월별 파일·출처·catalog를 함께 저장하고 구형 파일을 제거합니다. 반복 실행은 변경 없이 끝납니다. 구형 파일과 월별 파일을 동시에 두면 중단하므로 중복 저장하지 마세요.

파일 교체는 임시 파일과 `os.replace`를 사용하며 catalog를 마지막에 교체합니다. 작업 중 변경 파일의 이전 내용을 비공개 저널에 보존합니다. 중간 실패는 이전 상태로 돌아갑니다. 프로세스 강제 종료 후에는 다음 실행 또는 다음 명령으로 복구합니다.

```bash
.venv/bin/python -m collector recover
git status --short
git diff -- data
.venv/bin/python -m collector validate
```

복구 도중 운영자의 추가 편집을 발견하면 자동 덮어쓰지 않습니다. 먼저 저널과 Git 차이를 확인하세요. 저널과 관계없는 dirty 파일도 래퍼가 자동 삭제하지 않습니다. 운영 배치 자체가 실패하면 시작 시점의 깨끗한 Git HEAD로 해당 배치의 공개 변경을 되돌리고, 새로 만든 월 파일도 제거합니다. 이미 커밋 후 push만 실패했다면 커밋은 보존해 다음 실행에서 재전송합니다.

복구할 때는 필요한 월 파일만 단독 복사하지 말고 **그 시점의 catalog·sources·뉴스/브리핑 파일 집합**을 함께 검토합니다. 새 월의 파일도 커밋·아티팩트 대상입니다.

## 장기 운영 한계

이 변경은 브라우저의 카드·상세 데이터 로딩을 페이지 크기로 제한하고, 지속 실행 서버에서 수집 시 읽는 월 범위를 줄입니다. 전체 기사 5,000개 저장 제한은 제거했습니다.

다만 Astro는 여전히 전체 기사·발행 기록의 상세 페이지를 생성하며 Pagefind도 전체 검색 색인을 만듭니다. Git 이력·검색 결과 ID 목록·정적 파일 수·빌드 시간은 누적량에 따라 늘어납니다. 월별 분할만으로 이 증가가 사라지지는 않습니다. 정기적으로 `dist` 파일 수, Pages 빌드 시간·계정 파일 한도, 저장소 용량을 확인하세요. 실제 빌드/파일 한계에 가까워지면 과거 상세 페이지 별도 배포나 서버 검색 저장소를 검토해야 합니다. 한도 때문에 과거 기록을 자동 삭제하지 않습니다.

## 여러 달 브라우저 회귀 검사

운영 데이터에 가짜 기록을 넣지 않고 `.runtime` 아래 테스트 전용 자료를 만들 수 있습니다. 존재하지 않는 출력 디렉터리를 사용하세요. 이 빌드 결과는 테스트 전용이며 배포하면 안 됩니다.

```bash
.venv/bin/python tests/archive_fixture.py .runtime/browser-data
AI_BRIEF_DATA_DIR=.runtime/browser-data npm run build
AI_BRIEF_DATA_DIR=.runtime/browser-data npm run test:browser
# 테스트가 끝나면 환경 변수 없이 실제 데이터로 다시 빌드
npm run build
```

이 검사는 과거 월 검색·날짜/출처 필터·북마크와 12일을 넘는 히스토리 페이지 이동을 실제 검색 색인으로 확인합니다.
